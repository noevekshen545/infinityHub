Анализ бага: Custom-режим

Цепочка событий и план исправления для режима просмотра заметок
Цепочка возникновения бага
1. Создание новой заметки
page_notes_edit.html:4012
Bug Новая заметка в редакторе ещё не сохранена, поэтому noteId = '' (пустая строка).
noteId = ''
2. Переход в Custom-режим
URL: /notes/custom?id=&tpl=table
Bug Выбор Custom-режима или авто-переход дефолтного режима ведёт на страницу с пустым ID.
/notes/custom?id=&tpl=table
3. Пустая загрузка данных
page_notes_custom.html:1189
Bug Функция load() выходит сразу, так как ID пуст. Ничего не грузится.
if (!id) return;
4. Потеря настроек
page_notes_custom.html:1570
Bug saveSettings() видит пустой noteId и закрывает настройки, не сохраняя название и промпт.
if (!noteId) { closeSettings(); return; }
5. Игнорирование промпта ИИ
Логика ИИ
Bug ИИ получает ?tpl=table из URL и использует готовый шаблон «Таблица», игнорируя пользовательский промпт.
ИИ делает таблицу, игнорируя мой промпт
6. Неверное отображение после возврата
page_notes_custom.html:1203
Bug После создания заметки (с ID) свойств режима нет. При повторном открытии показывается дефолтное название «Таблица», промпт пуст.
modeName = p.custom_mode || 'Таблица'
План исправления

1. Редактор (page_notes_edit.html)

  • Перед любым переходом на /notes/custom (выбор режима, авто-переход) проверить наличие noteId.
  • Если noteId пуст, сначала создать заметку через существующий механизм сохранения (:5960).
  • Использовать полученный настоящий ID для перехода.

2. Custom-страница (страховка)

  • В saveSettings() при !noteId создать заметку через /api/notes/save.
  • Получить ID, присвоить noteId и записать свойства режима.
  • Аналогично реализовать автосохранение текста.

3. Тестирование (Playwright)

  • Полный цикл: новая заметка → Custom → ввод имени и промпта → «Создать».
  • Перезагрузка страницы.
  • Проверка: модалка показывает введённые данные.
  • Проверка: режим с галочкой появляется в «Мои режимы».
Согласование изменений

Важное замечание:

Пункт 1 плана исправления означает, что переход в Custom-режим из новой заметки автоматически создаст пустую заметку (иначе сохранить режим некуда). Требуется подтверждение этого поведения.
